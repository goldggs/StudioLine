# Project philosophy

## Interface

- Use a genuine, professional, restrained visual style, informed by research into professional design.
- Do not use gradients, glassmorphism, glow, shimmer, noise, or decorative animated text.
- Do not use emojis or em dashes.
- Favor clear names and direct actions over unnecessary abstractions.
- Keep features understandable and avoid overwhelming the user.

## Code quality

- Keep components modular and responsibilities explicit.
- Use strict type checking where supported.
- Handle errors gracefully, with clear recovery guidance and honest status reporting.

## Testing

- Build extensive tests across the codebase.
- Include adversarial, failure, and security scenarios, not just successful paths.
- Validate real Studio and Windows behavior in addition to simulated tests.

## Setup

- Make installation and everyday startup easy.
- Avoid requiring users to configure development tools or run a separate database server.
